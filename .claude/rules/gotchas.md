# Gotchas & Workarounds

## Known Quirks
- `isUserAllowed`/`USER_ALLOWED` keys must match RpcMethodMap spellings
  EXACTLY (e.g. `session.list` singular); a typo silently 403s a legit method.
  Keep in sync with the `createUserProxy` decorator.
- Disabled rows drop their browser halves from the boot graph: with the
  shipped `connection` row disabled, the GUI's wire client must come from this
  package's own `dsh.client` declaration + built `dist/client.js`.
- WebServer rejects duplicate `/api` prefix registrations (throws at boot):
  the shipped `connection` row must stay disabled while dsh-login's takeover
  is active.
- vitest resolves `@deepseek-ai/dsh-host-apiproxy` and
  `@deepseek-ai/dsh-client-connection` via aliases to the harness checkout
  (`DSH_HARNESS_CHECKOUT` env, default `E:/code/deepseek-harness`) — set it
  when running tests away from the default path.
- `dist/client.js` must be regenerated (`npm run build:client`) after
  upgrading `@deepseek-ai/dsh-client-connection`; the script re-stamps the
  module-loader id banner and fails loudly if the banner pattern is missing.
- Ownership sidecar persistence is best-effort; the in-memory map is
  authoritative and a corrupt file starts empty (fail-closed → admin-only
  until sessions are re-attributed).
- Legacy single-password flow is dead: the `password` ref stays configured but
  authenticates nobody (it only namespaces `${password}_USERS`).
- `tests/runner.mjs` / `integration-runner.mjs` predate multi-user; the
  `.spec.ts` files are canonical.

## Do Not Touch
- `package-lock.json` — auto-generated by npm
- `dist/client.js` — generated by `scripts/build-client.mjs`, not hand-edited
